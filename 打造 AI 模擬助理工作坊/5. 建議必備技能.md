## 建議必備技能

前面四章談的是「概念」與「方法」：怎麼連上工具、怎麼教它寫對程式、怎麼灌輸領域判斷力。但別忘了，不管是編程 Skill 還是模擬助理 Skill，說穿了都只是「放在資料夾裡的檔案」——一堆 Markdown 文件加上幾支範例程式。要讓這些檔案能夠長期、安全、可追溯地維護下去，你需要一套紮實的工程基本功。這最後一章，就是把這些「地基工程」一次補齊——它們不是可有可無的加分項，而是前面四章能不能真正落地的前提。

### 工作目錄與檔案架構

一套一致、可預期的資料夾結構，對人有幫助，對 AI Agent 更有幫助：當它知道「腳本永遠放在 `srcs/`、範例永遠放在 `examples/`」，就不用每次都花力氣去猜檔案該放哪裡，也比較不會生出重複或位置錯亂的檔案。這件事在人機協作的專案裡，重要性遠高於一般單人開發。

#### 建立工作目錄

建議每個模擬助理／Skill 專案，都採用同一套固定的根目錄慣例，例如：`.git/`、`.venv/`、`srcs/`、`examples/`、`dist/`、`projects/`，再加上 `README.md` 與 `pyproject.toml`。所有專案都照同一套規矩來，不只人容易上手，AI 在跨專案工作時也能沿用同一套「地圖」。

#### .git 目錄

這是 Git 用來記錄每一版檔案變化的隱藏資料夾。它的存在，正是讓「放心讓 AI 直接編輯 Skill 檔案」這件事變得安全的關鍵——任何一次不理想的自動寫入，都可以透過版本紀錄整個復原，不必擔心弄壞就回不去了。

#### .venv 目錄

這是專案獨立的 Python 執行環境，確保每個專案用的套件版本（例如 PyAEDT 版本）彼此不互相干擾。這一點在這門課的脈絡下特別重要：PyAEDT 的 API 會隨版本演進，一份針對舊版寫成的 Skill，換到新版環境可能整組失效，隔離環境能讓這種版本落差變得可控、可重現。

#### 其他常用目錄

- **srcs**：正式、會被長期維護的原始碼與 Skill 內容
- **examples**：範例與展示腳本，方便 AI 參考、也方便新人練習
- **dist**：打包或發佈用的輸出產物
- **projects**：個別客戶或案子的實際工作資料夾，與共用的 Skill 分開存放，避免專案資料與共用知識混在一起，日後也比較好決定哪些東西該被歸納進 Skill

### Git

一旦允許 AI Agent 直接改動你的知識庫（Skill 檔案），版本控制就不再是「加分項」，而是安全網。沒有它，就沒有辦法安心讓 AI 自動寫回學到的東西。

#### GitHub Desktop

對不熟悉命令列的工程師來說，GitHub Desktop 是一個親和力較高的圖形化入口，可以在合併任何變更之前，先用視覺化的方式瀏覽這次到底改了什麼。

#### Commit

一次 Commit，就是一個帶有說明文字的版本快照，記錄「改了什麼、為什麼改」。回到第四章的情境：當 AI 提議一次 Skill 更新時，「按下 Commit」就是那個真正代表「人已經審核並同意」的動作，而不只是把檔案存檔而已。

#### Diff

Diff 會精確標示兩個版本之間哪些行被改動過。這是審查 AI 寫回內容時最重要的工具——永遠先看過 Diff，確認改動合理、沒有把個案誤寫成通則，再決定是否 Commit，絕對不要對 AI 的自動寫入照單全收。

### uv for .venv

`uv` 是 Astral 推出的新一代 Python 專案管理工具，把過去 `pip`、`venv`、`poetry` 各自要處理的環境管理與套件依賴，整合成單一、速度快上許多的工具鏈，非常適合用來管理這種「每個 Skill／專案各自獨立環境」的工作方式。

#### .venv

使用 `uv` 時，它會自動在專案資料夾內建立對應的 `.venv`，不需要額外手動操作。

#### uv init --python 3.10

用來初始化一個新專案，並把 Python 版本明確釘選在 `pyproject.toml` 裡。版本一致性在這裡格外重要，因為 PyANSYS 系列套件對 Python 版本的相容性要求會隨版本而異，明確釘選版本，能確保這份 Skill 在別人的機器上也能重現一樣的行為。

#### uv sync

依照鎖定檔（`uv.lock`）把所有依賴套件精確安裝、還原到一致的版本，確保「AI Agent 實際操作的環境」跟「當初測試、驗證這份 Skill 時的環境」是同一套，避免「我這邊可以跑」的落差。

#### uv add

用來新增一項依賴（例如 `uv add pyaedt`），並自動更新鎖定檔。這是擴充模擬助理技術能力範圍最標準的方式——需要用到什麼套件，就用 `uv add` 明確加入，讓依賴關係一直保持透明、可追溯。

### Python 搭配 Packages

除了 PyANSYS 本身，模擬助理實務上還會頻繁用到幾個泛用型的 Python 套件，負責 AEDT 之外的數值運算與後處理工作。

#### 常用 Packages：numpy, scikit-rf, pandas, matplotlib, ezdxf

- **numpy**：數值陣列運算的基礎，幾乎所有後處理計算（頻域資料轉換、統計、內插）背後都靠它
- **scikit-rf**：專門處理 RF 網路與 S 參數的套件，適合用在 AEDT 之外做去嵌入（De-embedding）、級聯（Cascading）等網路運算
- **pandas**：表格化資料處理，適合整理掃描結果、跨設計變體比較
- **matplotlib**：客製化繪圖，補足 AEDT 內建報告畫面無法呈現的圖表需求
- **ezdxf**：讀寫 DXF 檔案，適合用程式化的方式匯入匯出 2D 幾何（例如 PCB 外框、天線圖案）
