## PyANSYS MCP介紹

上一章我們看到 AI Agent 已經有能力「動手做事」，但「動手」的前提是：它必須有辦法真的連上 AEDT、Mechanical、Fluent 這些模擬軟體，而不是只能紙上談兵、生成一段程式碼給你自己複製貼上執行。這一章要介紹的，就是讓 AI Agent 真正「長出手」的關鍵拼圖——PyANSYS 與 MCP。

### PyANSYS

PyANSYS 是 Ansys 官方維護的一系列開源 Python 函式庫的統稱，包括 PyAEDT（涵蓋 HFSS、Q3D、Circuit、Icepak、Maxwell 等 AEDT 內的所有工具）、PyMechanical、PyFluent、PyEDB、PyOptiSLang、PyTwin 等。這些函式庫的共同精神，是把原本只能在 GUI 上操作、或是用各產品專屬巨集語言（例如 VBScript、IronPython）寫的自動化流程，改寫成標準的 Python 物件導向 API。

這件事帶來的改變非常關鍵：第一，同一套自動化邏輯可以跨平台、跨版本執行，甚至可以在沒有畫面的伺服器上（Headless）批次執行、放進 CI/CD 流程；第二，因為是「正規的 Python 程式碼」，就能被版本控制（Git）管理，也能被 AI 讀懂、修改、產生；第三，也是這門課最重要的一點——PyANSYS 正是讓 AI Agent 從「只會講」變成「真的能動手做模擬」的那雙手。當我們說「訓練一個模擬助理」，本質上就是在訓練 AI 把任務正確地翻譯成一段合法的 PyANSYS 呼叫序列。

### MCP

MCP（Model Context Protocol，模型情境協定）是 Anthropic 於 2024 年底提出、目前已被業界廣泛採用的開放標準，用來規範「AI 應用程式（Host，例如 Claude Desktop、VS Code 的 Copilot Chat）」該如何發現並呼叫「外部工具伺服器（MCP Server）」所提供的能力。可以把它想像成 AI 世界的 USB-C：在 MCP 出現之前，每一種 AI 工具想要串接一個外部系統，都得各自客製一套整合方式；有了這個共通接口之後，任何支援 MCP 的 AI 客戶端，都能用同一套規則去「插上」任何一個 MCP Server，不需要重新開發整合邏輯。

MCP 定義了三種核心能力：Tools（工具，AI 可以呼叫並帶參數執行的函式，例如「開啟某個設計」「跑一次分析」）、Resources（資源，AI 可以讀取的唯讀資料，例如目前的模型狀態或結果檔案）、Prompts（提示樣板，預先設計好、可重複使用的任務模板）。當 AI 決定要執行某個動作時，它會先詢問已連接的 MCP Server「你有哪些工具可以用」，取得每個工具的名稱與參數格式（JSON Schema），再決定要呼叫哪一個、帶什麼參數，最後根據伺服器回傳的結果決定下一步——這就是上一章提到「Agent 能自主規劃並執行」的技術底層。

### PyANSYS MCP

把 PyANSYS 與 MCP 兩者疊在一起，就會得到「PyANSYS MCP」：一支獨立執行的伺服器程式，內部包了一整組 PyAEDT（或其他 PyANSYS 套件）的函式呼叫，並依 MCP 規格把它們包裝成一個一個定義清楚的 Tool，例如「建立 HFSS 設計」「指定波導端口」「執行分析」「匯出 S 參數」。任何支援 MCP 的 AI 客戶端，只要連上這個伺服器，就能像操作選單一樣，一步一步呼叫這些工具，並即時看到每一步的成功或失敗、拿到真實的回傳資料。

這跟單純「叫 AI 幫我寫一段 PyAEDT 程式碼」有本質上的差別：後者是靜態生成、你得自己執行、出錯了你得自己抓；前者是動態互動、每一步都有即時回饋，AI 可以根據上一步的結果決定下一步該怎麼修正。這正是把「只會聊天的助手」升級成「真正能執行模擬任務的代理人」的臨門一腳。

這不是紙上談兵的概念——截至目前，PyANSYS 官方文件站（[docs.pyansys.com](https://docs.pyansys.com/)）已經列出了好幾支正式維護的 MCP Server，而且數量還在持續增加：**PyAEDT MCP**（對應 HFSS、Q3D、Icepak、Circuit、Maxwell、Mechanical、EMIT、RMXprt、HFSS 3D Layout 等 AEDT 內的工具）、**PyMechanical MCP**、**PyFluent MCP**、**PyMAPDL MCP**、**PyLumerical MCP**、**PyCFX MCP**。也就是說，各位不需要從零開始「發明」串接方式，多數主流 Ansys 產品已經有現成、官方維護的 MCP Server 可以直接拿來用或參考其架構。這門課會以 PyAEDT MCP 作為示範對象，因為它涵蓋的產品範圍最貼近電子/電磁模擬的日常工作。

### 安裝與連結

有了觀念，接下來看實際落地會長什麼樣子。這裡以官方的 **PyAEDT MCP**（[github.com/ansys/pyaedt-mcp](https://github.com/ansys/pyaedt-mcp)）為例，示範最基本的安裝與連結流程；其他 PyANSYS MCP 產品（PyFluent MCP、PyMechanical MCP 等）的安裝與連結方式幾乎一致，差別只在套件名稱與可用工具內容。

#### 安裝方式

PyAEDT MCP 的執行環境需求是 Python 3.12 以上，並且本機已安裝 AEDT 2022 R2 以上版本（或有一台可連線的遠端 AEDT gRPC 服務）。安裝方式有兩種常見做法：

第一種是「免安裝、直接執行」，適合快速試用——用 `uvx` 直接從原始碼倉儲拉下來執行，不需要事先安裝到專案環境裡：

```bash
uvx --from git+https://github.com/ansys/pyaedt-mcp.git ansys-aedt-mcp
```

第二種是「安裝到本機環境」，適合正式納入專案（例如第五章會介紹的 `.venv` 與 `uv` 工作流程）：

```bash
pip install git+https://github.com/ansys/pyaedt-mcp.git
# 或使用 uv
uv pip install git+https://github.com/ansys/pyaedt-mcp.git
```

安裝完成後，記得先啟動 AEDT 並開啟 gRPC 服務（正常啟動 AEDT 就會自動開啟 gRPC，或用指令手動指定埠號，例如 `"C:\Program Files\ANSYS Inc\v261\AnsysEM\ansysedt.exe" -grpcsrv 50051`），再啟動 MCP Server 本身：

```bash
ansys-aedt-mcp
# 常見變化用法：
ansys-aedt-mcp --connect --machine localhost --port 50051   # 啟動時直接連線既有工作階段
ansys-aedt-mcp --transport http --http-host 127.0.0.1 --http-port 8080   # 改用 HTTP 而非預設 STDIO
```

#### 連結方式

連結的步驟，是在 AI 客戶端的設定檔中登記這個 MCP Server。以 VS Code 為例，在 `settings.json`（或工作區的 `.vscode/mcp.json`）中加入：

```json
{
  "mcp": {
    "servers": {
      "pyaedt-mcp": {
        "command": "uvx",
        "args": [
          "--index-strategy", "unsafe-best-match",
          "--from", "git+https://github.com/ansys/pyaedt-mcp.git",
          "ansys-aedt-mcp"
        ]
      }
    }
  }
}
```

若使用 Claude Desktop，則是在 `claude_desktop_config.json` 中加入結構幾乎相同的設定：

```json
{
  "mcpServers": {
    "pyaedt-mcp": {
      "command": "uvx",
      "args": [
        "--from", "git+https://github.com/ansys/pyaedt-mcp.git",
        "ansys-aedt-mcp"
      ]
    }
  }
}
```

存檔後重新啟動客戶端，它就會自動呼叫這個指令把 Server 啟動起來，並詢問「你有哪些工具可以用」，把結果顯示在介面上。驗證連線是否成功最簡單的方式，就是直接請 AI「列出目前可用的工具」，或請它嘗試一個最小任務（例如「開啟 AEDT 並回報目前的版本號」），確認整條鏈路——從 AI 客戶端、到 MCP Server、到 PyAEDT、到真正的 AEDT 程式——是通的。
