PyAEDT-MCP

Bring an AI copilot into Ansys Electronics Desktop

A Model Context Protocol server for AEDT, built on PyAEDT + FastMCP

aedt-mcp.docs.pyansys.com/version/stable

What is PyAEDT-MCP?

  • An MCP server for Ansys Electronics Desktop (AEDT)
  • Bridges any MCP client → a persistent PyAEDT Python session
  • Exposes a curated tool surface: lifecycle, projects, scripting, analysis, inspection, export
  • Built with FastMCP; can auto-connect to a running AEDT on startup
"Your AI agent, sitting directly next to the AEDT solver."

Why an MCP layer for AEDT?

Before

  • Copy/paste Tcl or PyAEDT snippets between chat & IDE
  • No shared context between the LLM and AEDT state
  • Restarting AEDT for every experiment

With PyAEDT-MCP

  • The agent runs tools directly against a live AEDT session
  • Persistent Python interpreter across calls
  • Screenshots, logs, results streamed back to the model

Architecture at a glance

Install & launch

Prereqs: Python 3.12+, AEDT 2022 R2+, local or reachable AEDT.

## One-shot with uvx
uvx --from git+https://github.com/ansys/pyaedt-mcp.git \
    ansys-aedt-mcp

## Or install with pip
pip install git+https://github.com/ansys/pyaedt-mcp.git
## Start AEDT in gRPC mode
"C:\Program Files\ANSYS Inc\v261\AnsysEM\ansysedt.exe" \
    -grpcsrv 50051

## Server + auto-connect
ansys-aedt-mcp --connect --machine localhost --port 50051
ansys-aedt-mcp --transport http --http-host 127.0.0.1 --http-port 8080
ansys-aedt-mcp --include-context --dynamic-tool-discovery

Typical first call sequence

  1. check_aedt_installed
  2. check_aedt_status
  3. launch_aedt or connect_to_aedt
  4. open a project or create_design
  5. drive the rest with tools or run_python_code

Best practices

Session

Reuse the connection — each launch_aedt is expensive. Always check_aedt_status first; shut down with disconnect_from_aedt.

Scripting

Prefer many small run_python_code calls to inspect intermediate state. Ask for get_guidelines_for before generating PyAEDT code.

Data

Extract only what you need, cache in Python vars, then disconnect — keep post-processing off AEDT.

Visualization

Save the project, then screenshot after geometry, meshing, and analysis for visual checkpoints.

Workflow

One dedicated tool per logical step. save_project after expensive stages so runs are resumable.

Performance

Minimize AEDT restarts. Use AEDT's parametric solver for sweeps. Process results in Python.
