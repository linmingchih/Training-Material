第三章 PyAEDT-MCP 連線與操作

### 什麼是 MCP

MCP（Model Context Protocol，模型情境協定）是用來規範「AI 應用程式（Host，例如 VS Code Copilot Chat、Claude Desktop）」與「外部工具伺服器（MCP Server）」之間該怎麼溝通的開放標準。有了這套共通規則之後，任何支援 MCP 的 AI 客戶端，都能用同一套方式接上任何一個 MCP Server，不需要針對每一套工具重新開發整合邏輯。

MCP 定義了三種核心能力：

- **Tools**：AI 可以帶參數呼叫執行的函式，例如「開啟某個設計」「跑一次分析」。
- **Resources**：AI 可以讀取的只讀資料，例如目前模型狀態或結果檔。
- **Prompts**：預先設計好、可重複使用的任務模板。

當 AI 決定要執行某個動作時，會先詢問已連接的 MCP Server「你有哪些工具可以用」，取得每個工具的名稱與參數格式（JSON Schema），再決定要呼叫哪一個、帶什麼參數，最後根據伺服器回傳的結果決定下一步。這一來一往的互動，讓 AI 能夠真正驅動 AEDT 執行任務，而不只是生成一段程式碼交給你自己複製貼上執行。

#### MCP 是給 AI 用的，不是給人用的

MCP Server 暴露出來的 Tools，名稱、參數格式、回傳結構都是以 JSON Schema 描述，設計目的是讓 LLM 能精確解讀、自行拼出呼叫參數，而不是提供人類友善的 CLI 或 GUI。這代表 MCP Server 並不適合人當作日常命令列工具直接呼叫：沒有人友善的幫助說明、沒有自動補全，回傳的內容也往往是結構化資料而非人類易讀的文字。人工若需要自己執行一次性或重複性高的任務，仍然應直接寫 PyAEDT 腳本執行（如第 2 章），而非透過 MCP Server。MCP 這層存在的意義，是讓 AI Agent 能夠自主發現與呼叫工具，不是取代人類直接使用 PyAEDT 的方式。

#### MCP 無法記憶

MCP 協定本身不包含任何「記憶」機制：每次 AI 呼叫工具都是一次獨立的 Tool Call，MCP Server 本身不會記得上一次你說過什麼、上一次抓過什麼資料。真正會「記住」上下文的，是 AI 客戶端那邊的對話視窗（在這次對話發送給模型的前後訊息），一旦對話結束、視窗被清空，AI 下次就忘記這次模型怎麼呼叫、會遇到什麼問題。值得一提的是，AEDT 程序本身的狀態（例如目前有哪個專案開著）會一直存在，不會因為對話結束而消失，但這是 AEDT 自己的狀態，不是 MCP 協定提供的記憶能力。想要讓 AI 每次都記得你們家的模擬慣例，需要靠下一章介紹的 Skill 檔案把知識固化成文字，而不能依賴 MCP 本身去記住任何事。

### 安裝 PyAEDT MCP

PyAEDT MCP 需要 Python 3.12 以上，並且本機已安裝 AEDT 2022 R2 以上（或有可連線的遠端 AEDT gRPC 服務）。

方式一：免安裝、直接執行，適合快速試用：

```bash
uvx --from git+https://github.com/ansys/pyaedt-mcp.git ansys-aedt-mcp
```

方式二：安裝到本機環境，適合正式納入專案：

```bash
pip install git+https://github.com/ansys/pyaedt-mcp.git
# 或使用 uv
uv pip install git+https://github.com/ansys/pyaedt-mcp.git
```

#### 為何要對齊 PyAEDT 與 pyaedt-mcp 的版本

pyaedt-mcp 內部實際上就是包一層 MCP 介面，在裡面呼叫 PyAEDT 的 API 來驅動 AEDT。如果 pyaedt-mcp 安裝時帶進來的 PyAEDT 版本，與它實際需要呼叫的 API 不相容（例如那支 API 在新版 PyAEDT 裡改名，或舊版 PyAEDT 根本沒有這個函式），MCP 工具在執行時就會直接報錯，而且這種錯誤對 AI 來說往往不易判斷是自己呼叫參數錯，還是底層版本不合。另一個實務上容易被忽略的風險是：若將 pyaedt-mcp 裝在與其他自動化腳本共用的全域 Python 環境，安裝 pyaedt-mcp 時帶進來的 PyAEDT 版本，可能會覆蓋掉其他腳本原本需要的特定 PyAEDT 版本，造成別套自動化程式當場壞掉。因此實務上建議：

- 把 pyaedt-mcp 裝在獨立的虛擬環境（呼應第 2 章提到的虛擬環境建議），不與其他專案共用。
- 升級 AEDT 版本後，同步確認 pyaedt-mcp 依賴的 PyAEDT 版本仍然支援新版 AEDT，不要假設舊版那套自動安裝的版本在新版就一定能用。
- 若發現工具呼叫失敗，先檢查當前 pyaedt-mcp 所依賴的 PyAEDT 版本號，再確認是否與本機 AEDT 版本相容，而不要直接假設是 AI 呼叫這層出錯。

### 啟動流程

先確保 AEDT 已啟動且 gRPC 服務已開啟（正常啟動 AEDT 會自動開啟 gRPC，也可用指令手動指定埠號）：

```bash
"C:\Program Files\ANSYS Inc\v242\AnsysEM\ansysedt.exe" -grpcsrv 50051
```

接著啟動 MCP Server 本身：

```bash
ansys-aedt-mcp
# 常見變化用法：
ansys-aedt-mcp --connect --machine localhost --port 50051   # 啟動時直接連線既有工作階段
ansys-aedt-mcp --transport http --http-host 127.0.0.1 --http-port 8080   # 改用 HTTP 而非預設 STDIO
```

### 在 AI 客戶端登記連結

以 VS Code 為例，在 `settings.json`（或工作區的 `.vscode/mcp.json`）中加入：

```json
{
  "mcp": {
    "servers": {
      "pyaedt-mcp": {
        "command": "uvx",
        "args": [
          "--index-strategy", "unsafe-best-match",
          "--from", "git+https://github.com/ansys/pyaedt-mcp.git",
          "ansys-aedt-mcp"
        ]
      }
    }
  }
}
```

若使用 Claude Desktop，則是在 `claude_desktop_config.json` 中加入結構幾乎相同的設定：

```json
{
  "mcpServers": {
    "pyaedt-mcp": {
      "command": "uvx",
      "args": [
        "--from", "git+https://github.com/ansys/pyaedt-mcp.git",
        "ansys-aedt-mcp"
      ]
    }
  }
}
```

### 驗證連線

存檔後重新啟動客戶端，它會自動呼叫這個指令把 Server 啟動起來，並詢問「你有哪些工具可以用」，把結果顯示在介面上。驗證連線是否成功最簡單的方式，就是直接請 AI「列出目前可用的工具」，或請它嘗試一個最小任務（例如「開啟 AEDT 並回報目前版本號」），確認整條鏈——從 AI 客戶端、到 MCP Server、到 PyAEDT、到真正的 AEDT 程式——是通的。
