第二章 PyAEDT AI Coding 專案環境建置
---

### 專案開發準備

在正式安裝 PyAEDT、啟動 AEDT 之前，建議先按以下順序備妥開發環境，之後每個新專案都可以照同一套流程重複執行：

1. **開啟 AI 編輯器，檢查 AI Chat 連線**：確認 VS Code（或其他支援 AI Agent 的編輯器）能正常對話、回應請求，這是後續請 AI 協助寫程式、除錯的前提。
2. **建立工作目錄**：為這個專案建立一個獨立的資料夾，之後的虛擬環境、程式碼、Git 版本紀錄都會放在這裡，避免與其他專案的檔案混在一起。
3. **在工作目錄中安裝 Python 3.12 的 `.venv` 及所需套件**：依照下一節「Python 環境準備」建立虛擬環境，並安裝 `pyaedt`（或 `ansys-aedt-core`）、`pyaedt-mcp`（下一章連結 AI Agent 會用到）與其他專案需要的套件（例如 `numpy`、`pandas`）。由於 `pyaedt-mcp` 只支援 Python 3.12 以上版本，本教材統一以 Python 3.12 建立 `.venv`。
4. **建立 `.git`**：在工作目錄執行 `git init` 建立版本控制，讓之後 AI Agent 或人工修改的每一次程式碼變更都能被追蹤、回溯（詳見第 5 章「為何要用 Git 保存版本」）。

```bash
mkdir my-pyaedt-project
cd my-pyaedt-project

uv venv --python 3.12
.venv\Scripts\activate
uv pip install ansys-aedt-core pyaedt-mcp

git init
```

### Python 環境準備

PyAEDT 搭配 `pyaedt-mcp` 時需要使用 Python 3.12 以上版本，本教材統一以 Python 3.12 建立虛擬環境。實務上建議不要直接用系統全域的 Python，而是為每個專案建立獨立的虛擬環境，避免不同專案之間的套件版本衝突：

```bash
# 使用標準 venv
py -3.12 -m venv .venv
.venv\Scripts\activate

# 或使用更快的 uv
uv venv --python 3.12
.venv\Scripts\activate
```

`uv` 是較新的 Python 套件管理工具，安裝速度明顯快於傳統 `pip`，也能一併管理虛擬環境，這點在第 3 章介紹 MCP 工具安裝時也會再次用到。

#### pip 與 uv 的選擇

兩者都能安裝 Python 套件，但行為上有幾個實用差異：

- **速度**：`uv` 用 Rust 實作並帶有快速字元強化（cache），安裝同樣的 `pyaedt` 及其依賴套件，通常比 `pip` 快好幾倍，尤其在需要重複重建環境（例如 CI 每次從零建虛擬環境）時差異更明顯。
- **依賴解析一致性**：`uv` 預設會產生精確的 lock 檔（`uv.lock`），確保別人或別台機器安裝出來的套件版本完全一致：`pip` 預設不產生 lock 檔，需另外搭配 `pip freeze` 才能達到類似效果。
- **虛擬環境整合**：`uv venv` / `uv pip install` 將建環境與安裝套件整合成同一套指令，`pip` 則需搭配 `venv` 模組分開使用。
- **相容性**：兩者存在的套件庫相同（PyPI），`uv` 可以直接讀 `requirements.txt`，安全交換或回退到 `pip` 沒有障礙。

實務上建議：單人快速試用兩者都行；若專案需要多人協作、多台機器重現環境（例如團隊共同維護自動化腳本），優先考慮 `uv`。

#### 為什麼虛擬環境對 PyAEDT 尤其重要

PyAEDT 的版本與安裝的 AEDT 版本之間有密切的對應關係：新版 PyAEDT 可能不再支援舊版 AEDT（例如舊於 2022 R2），舊版 PyAEDT 也可能缺少新版 AEDT 才有的 API。實務上很常見同時維護多個專案，分別連接不同版本的 AEDT（例如舊專案固定在 2023 R1，新專案已升級到 2024 R2），這時候若所有專案共用同一套全域 Python 環境，升級某一個專案的 PyAEDT 版本很容易讓另一個專案當場壞掉。為每個專案建立獨立的虛擬環境，才能讓不同版本的 PyAEDT（以及其他依賴套件）安心共存，不會因為升級其中一個專案而意外改變別專案的行為。

### 安裝 PyAEDT

```bash
pip install pyaedt
# 或（新包名，功能相同）
pip install ansys-aedt-core
```

PyAEDT 套件名稱已由 `pyaedt` 逐步改為 `ansys-aedt-core`，兩者目前都可安裝、import 方式相容，新專案建議直接使用 `ansys-aedt-core`。安裝完成後，需確認本機已安裝 AEDT（建議 2022 R2 以上）並擁有有效 License。

#### 離線安裝

若機器沒有對外網路（例如隔離的模擬伺服器、內網環境），可以到 PyAEDT 的 GitHub Releases 頁面（https://github.com/ansys/pyaedt/releases）下載對應版本的原始碼壓縮檔或 wheel 檔，帶回離線機器安裝：

```bash
# 先在有網路的機器下載，例如 v0.15.0 的 wheel 檔
# 再帶到離線機器上，用 pip 從本機檔案安裝
pip install ansys_aedt_core-0.15.0-py3-none-any.whl
```

若還需要一併帶齊相依套件，可以在有網路的機器上先用 `pip download -d ./offline_packages ansys-aedt-core` 把整包相依套件下載到資料夾，再把整個資料夾複製到離線機器，用 `pip install --no-index --find-links=./offline_packages ansys-aedt-core` 安裝，避免安裝時因缺少某個間接依賴而失敗。

### 啟動 AEDT

PyAEDT 提供 `Desktop` 物件來啟動或連接 AEDT：

```python
from ansys.aedt.core import Desktop

# 全新啟動一個 non-graphical 的 AEDT（適合 headless / 伺服器批次執行）
d = Desktop(version="2024.2", non_graphical=True, new_desktop=True)

# 或連接已經開啟的 AEDT作業面、保留畫面方便除錯
d = Desktop(version="2024.2", new_desktop=False)
```

常用參數與概念：

- `version`：指定使用哪一版 AEDT（可以同機安裝多個版本，不指定時預設抓取最新已安裝版本）。
- `non_graphical`：`True` 則不開圖形介面，適合沒有畫面的伺服器或批次作業，也是遠端主機、CI/CD 管線上執行模擬的必選項（沒有螢幕時直接開 GUI 會失敗）；`False` 則會彈出 GUI，適合需要人工確認模型的場合。需要注意的是，`non_graphical=True` 不代表模擬跑得更快，只是不繪製介面，求解效能本身不會差。
- `new_desktop`：`True` 會另開一個全新的 AEDT 程序；`False` 則會優先嘗試連接目前已經在執行中的作業面。

#### 結束工作階段：`release_desktop`

程式執行結束後，記得呼叫 `release_desktop` 釋放資源，避免 AEDT 程序殘留在後台一直佔用 License：

```python
# 預設會一併關閉專案與 AEDT，適合批次腳本執行完就完全退出
desktop.release_desktop(close_projects=True, close_desktop=True)

# 只想斷開連線、保留 AEDT 視窗不關（方便人工繼續看畫面）
desktop.release_desktop(close_projects=False, close_desktop=False)
```

`close_projects` 控制是否順便儲存並關閉目前開啟的專案，`close_desktop` 控制是否連 AEDT 本身的程序一起結束。若忘記呼叫這一步，專案可能持續持有 License，並留下一個沒有人互動的 AEDT 程序在後台。

#### 鎖檔（.lock）與 `remove_lock`

AEDT 在開啟專案時會在同目錄產生一個 `xxx.aedt.lock` 鎖檔，用來避免多個作業面同時寫入同一個專案造成損壞。正常關閉時鎖檔會自動刪除，但若程式意外中斷、或 `release_desktop` 沒被呼叫到，鎖檔會殘留下來，導致下次開啟同一專案時報錯或變成只讀。確認確實沒有其他人/程式正在使用該專案後，可以直接手動刪除這個 `.lock` 檔，或在 Python 中呼叫 PyAEDT 提供的工具函式清除：

```python
from ansys.aedt.core.generic.general_methods import remove_project_lock

remove_project_lock(r"D:\projects\my_design.aedt")
```

這在自動化流程中特別實用：每次執行前先檢查並清除舊鎖檔，可以避免因為上一次意外中斷而讓這一次批次作業失敗。

### 常見環境問題排查

- **License 連不上**：確認 `ANSYSLMD_LICENSE_FILE` 環境變數或 License 伺服器設定正確，並確認這台機器能連到 License Server。
- **版本不相容**：`version` 參數與實際安裝的 AEDT 版本字串格式需一致（例如 `"2024.2"`），多版本共存時尤其容易打錯。
- **前一次結束沒釋放乾淨**：若上次執行中斷，可能留下殘留的 AEDT 程序或 `.lock` 鎖檔，需手動關閉程序，或先呼叫 `remove_project_lock` 清除鎖檔後再重試。
- **Path / 權限**：確認安裝目錄權限、或 AEDT 安裝路徑正確登錄在系統變數中，尤其在企業共用主機上安裝時。
