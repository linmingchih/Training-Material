01. PyAEDT 與 AI Coding 基礎

### PyANSYS

PyANSYS 是 Ansys 官方維護的一系列開源 Python 函式庫的統稱，目前已涵蓋約 70% 現有的 Ansys 模擬工具（HFSS、Mechanical、Fluent、MAPDL、EDB 等），完整清單可在官方文件站查到。

與傳統上「只能在各產品內部才能執行」的巨集式腳本語言（例如 VBScript、IronPython）不同，PyANSYS 是標準的 Python 套件，可以在任何裝有 Python 的環境（本機、伺服器、CI/CD 管線）中透過外部行程呼叫並控制 Ansys 產品，不需要先打開對應軟體的圖形介面。

因為是正規的 Python 套件，也就能自由串接第三方 Python 套件（例如 NumPy、Pandas、Matplotlib 做數值處理與繪圖，或是 FastAPI、Flask 做服務化），甚至可以輕鬆地在它之上打造專屬 GUI 或網路服務，而不是被綁死在單一產品的腳本環境裡。

#### 網路資源

- PyANSYS 官方文件站：https://docs.pyansys.com/ ，網站中除了各套件的安裝說明外，也整理了每個 PyANSYS 套件的 API 參考、教學範例與版本更新紀錄，是查詢所有 PyANSYS 相關資訊的起點。

### PyAEDT

PyAEDT 是 PyANSYS 家族中，專門用來自動化 **Ansys Electronics Desktop（AEDT）** 的套件，支援的工具包括 HFSS、HFSS 3D Layout、Q3D Extractor、Q2D Extractor、Circuit、Icepak、Maxwell 2D/3D、Mechanical（AEDT 內建）、EMIT、RMXprt、Twin Builder 等，涵蓋電子、電磁、訊號完整性、電源完整性到熱模擬的常見需求。

有個基本觀念可以幫助理解 PyAEDT：GUI 上能做的每一項操作，幾乎都有對應的 API 可以呼叫；因此只要能在 GUI 上想清楚一次完整模擬該有的操作順序（建模 → 設定材料 → 定義 Port/Boundary → 設定模擬 → 執行 → 取結果），這個順序基本上就是之後程式呼叫 API 的順序。


#### 網路資源

- PyAEDT 官方文件：https://aedt.docs.pyansys.com/version/stable/#， 當中提供完整的 API 參考與範例腳本（Examples）
- PyAEDT GitHub 原始碼：[PyAEDT](https://github.com/ansys/pyaedt)，遇到 API 使用問題或懷疑是套件本身的錯誤，也可以在該儲存庫的 Issues 頁面搜尋是否有人問過類似問題，或提出新的 issue 詢問。

#### 材料設定與建模

**3D Modeler**
負責 AEDT 內三維幾何的建立與編輯，涵蓋基礎圖元（長方體、圓柱、多邊形等）到進階操作（布林運算、圓角、陣列複製等）。

**Layout**
針對 PCB / IC 封裝等版圖結構進行操作，例如疊層（Stackup）設定、走線、過孔、網路（Net）管理，對應 HFSS 3D Layout 模組。

**Schematic**
用來建立與編輯電路原理圖，對應 Circuit（Nexxim）模組，可放置元件、連接網路、匯入 S 參數模型。

#### Port & Boundary

模擬前必須正確定義激勵源（Port，例如波導埠、集總埠、差動埠）與邊界條件（Boundary，例如完美電導體、輻射邊界、對稱邊界），這些設定直接影響模擬結果是否正確、是否收斂。

#### 模擬與掃頻設定

包含網格（Mesh）設定與模擬收斂準則（例如 HFSS 的 Delta S 收斂條件），以及頻率掃描（Sweep）方式的選擇（離散、內插、快速掃描），這些都會影響模擬精度與所需的運算時間。

#### 啟動模擬

模擬可以在本機執行，也可以連線到遠端伺服器執行，或是透過分散式運算（Distributed Solve）把單一模擬工作拆分到多台機器 / 多個核心上加速求解，這對大型模型尤其重要。

#### 模擬資料抓取

模擬完成後，可以透過 PyAEDT 直接抓取報表資料（例如 S 參數、阻抗曲線）與場分布圖（Field Plot）。抓取方式有兩種：一種是直接匯出 GUI 報表對應的圖表（例如 PNG、CSV 曲線圖），另一種是取出底層的原始數值，交給 Python 在 AEDT 之外另行後處理、繪圖或整理成報告，不需要手動在 GUI 裡逐一匯出。

### PyAEDT Script 使用方式

PyAEDT 腳本大致可以分成兩種執行方式，差別在於「AEDT 是被誰啟動的」。

**外部執行**：由 Python 腳本主動啟動或連接 AEDT（透過前面提到的 `Desktop` 物件），AEDT 只是被呼叫的後端。這種方式最有彈性，可以進一步包裝成：

- **CLI**：把腳本包成命令列工具，帶參數（例如檔案路徑、掃頻範圍）批次執行，適合排程或 CI/CD。
- **GUI**：在 PyAEDT 之上疊一層自製的桌面介面（例如 Tkinter、PyQt），讓不熟 Python 的同事用按鈕操作，而不需要碰程式碼。
- **Web service**：包裝成 FastAPI、Flask 這類網路服務，讓其他系統（包括後續章節介紹的 AI Agent / MCP）透過 API 呼叫，適合團隊共用或跨系統整合。

**AEDT 內執行**：AEDT 本身也提供「Tools > Run Script」的選單，可以直接在已開啟的 AEDT 工作階段中執行 Python／IronPython 腳本。此時腳本是在 AEDT 內部行程中運行，直接沿用當下已開啟的專案與設計（`oDesktop`），不需要另外啟動一個新的 AEDT 行程，適合在 GUI 操作到一半時，臨時插入一段程式化的批次動作。

### AI 對 Coding 的改變

過去幾年，AI 對軟體開發的影響，已經從「幫忙寫一段程式碼建議」演變成「與一個具備自主行動能力的 Coding Agent 協作」。史丹佛大學開設的 CS146S：The Modern Software Developer 課程網站（https://themodernsoftware.dev/）對這個轉變有一段精準的描述：大型語言模型已經把軟體開發從「主要靠人工手寫程式碼」的流程，變成「開發者與能力越來越強的 Coding Agent 協作」的流程，這個轉變也連帶要求開發者用新的方式定義意圖、拆解工作、協調工具，讓 Agent 能真正參與到複雜專案裡。

這個轉變背後的關鍵技術，就是讓 LLM 具備「工具呼叫（Tool Calling）」的能力：AI 不再只是吐一段文字讓你複製貼上，而是可以自己決定「現在要呼叫哪個工具、帶什麼參數」，再依照工具回傳的結果決定下一步。放到 AEDT 的情境裡，這代表 AI 不只能生成一段 PyAEDT 程式碼，還能真的去呼叫、去執行、去看結果、去修正——前提是它得先有辦法「連上」AEDT。而 MCP，正是讓 AI Agent 能夠標準化地連上外部工具（包括 AEDT）的關鍵協定，下一章會介紹具體連結方式。

#### 最新趨勢：課程教材的大翻新

這個轉變的速度到底有多快，看史丹佛這門課本身的變化最有感覺。CS146S 在 2026 年秋季公布的最新版課程大綱，授課教授直接表示：2025 年秋季那一版課程，有 85% 的教材已經過時。原因也直接：2025 年 11 月 Claude Opus 4.5 推出之後，Coding Agent 的能力出現一次明顯跳躍，連帶讓軟體開發的工作方式徹底改變，於是這門課幾乎整個重新設計。

新版課程要學生學的，已經不是「怎麼更熟練地手寫程式碼」，而是：Agent Skills、進階 Context Engineering、MCP、Agent-ready 的程式碼庫、Agentic Code Review、安全性、平行背景 Agent（Parallel Background Agents）、Software Factory。學生甚至必須直接向真實世界的生產級開源專案提交 PR，目前課程合作的專案包括 Browserbase、HeyGen、OpenHands、Milvus、CrewAI、Warp、Vercel、Unsloth、Anyscale 等一批 AI 專案。

這門課的核心命題是：在 LLM 時代，AI-native Developer 會成為軟體組織裡最重要的一種角色——過去大學教的是「怎麼寫軟體」，現在史丹佛教的則是「怎麼管理一群 Agent 寫軟體」。放回 AEDT 的情境，這正是這一系列教材想帶各位練習的方向：不是取代寫 PyAEDT 的能力，而是學會怎麼組織、監控，並持續優化一整群會動手做模擬的 AI Agent。

### 下載與授權

使用者可以直接下載 PyAEDT 並安裝使用，不需要額外取得授權（PyAEDT 本身是開源、免費的）。但實際執行模擬時，仍然需要一套有效的 Ansys AEDT License，PyAEDT 只是驅動 AEDT 的介面，並不能取代底層產品的授權需求。
