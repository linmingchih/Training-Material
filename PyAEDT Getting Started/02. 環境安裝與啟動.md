02. 環境安裝與啟動
---
這一章只处理「Python / PyAEDT 安裝」與「啟動 AEDT」兩件事，連結 AI Agent（MCP）的部分留到下一章。

### Python 環境準備

PyAEDT 目前建議搭配 Python 3.10 以上的版本。實務上建議不要直接用系統全域的 Python，而是為每個專案建立独立的虛擬環境，避免不同專案之間的套件版本衝突：

```bash
# 使用標準 venv
python -m venv .venv
.venv\Scripts\activate

# 或使用更快的 uv
uv venv
.venv\Scripts\activate
```

`uv` 是較新的 Python 套件管理工具，安裝速度明顯快於傳統 `pip`，也能一併管理虛擬環境，這很論點在第 5 章介紹 MCP 工具安裝時也會再次用到。

### 安裝 PyAEDT

```bash
pip install pyaedt
# 或（新包名，功能相同）
pip install ansys-aedt-core
```

PyAEDT 套件名稱已由 `pyaedt` 逐步改為 `ansys-aedt-core`，兩者目前都可安裝、import 方式相容，新專案建議直接使用 `ansys-aedt-core`。安裝完成後，需確認本機已安裝 AEDT（建議 2022 R2 以上）並擁有有效 License。

### 啟動 AEDT

PyAEDT 提供 `Desktop` 物件來啟動或連接 AEDT：

```python
from ansys.aedt.core import Desktop

# 靛新啟動一個 non-graphical 的 AEDT（適合 headless / 伺服器批次執行）
d = Desktop(version="2024.2", non_graphical=True, new_desktop=True)

# 或連接已經開啟的 AEDT作業面、保留畫面方便除錯
d = Desktop(version="2024.2", new_desktop=False)
```

常用參數與概念：

- `version`：指定使用哪一版 AEDT（可以同機安裝多個版本，不指定時預設拓取最新已安裝版本）。
- `non_graphical`：`True` 則不開圖形介面，適合沒有畫面的伺服器或批次作業；`False` 則會彈出 GUI，適合需要人工確認模型的場合。
- `new_desktop`：`True` 會另開一個全新的 AEDT 進程；`False` 則會優先嘗試連接目前已經在執行中的作業面。

程式執行結束後，記得呼叫 `d.release_desktop()` 釋放資源，避免 AEDT 進程残留在後台一直佔用 License。

### 常見環境問題排查

- **License 連不上**：確認 `ANSYSLMD_LICENSE_FILE` 環境變數或 License 伺服器設定正確，並確認這台機器能連到 License Server。
- **版本不相容**：`version` 參數與實際安裝的 AEDT 版本字串格式需一致（例如 `"2024.2"`），多版本共存時尤其容易打錯。
- **前一次結束沒釋放干淨**：若上次執行中斷，可能留下孫孤的 AEDT 進程或鎖檔，需手動關閉後再重試。
- **Path / 權限**：確認安裝目錄權限、或 AEDT 安裝路徑正確登錄在系統變數中，尤其在企業共用主機上安裝時。
